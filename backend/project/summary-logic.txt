1. /ask analyzes intent and resolves PDF/section scope through orchestration/routing.py before calling the summary workflow. Ambiguous documents return clarification choices; see knowledge-base-routing.txt.
2. summary/storage.py lists and fetches ALL stored chunks for the requested document in numeric chunk order. It never searches vectors, samples chunks, or extracts the PDF again. Missing/foreign chunks fail visibly.
3. summary/chunks.py orders and packs text into token-budgeted passages, splits oversized text without truncation, and preserves physical PDF page ranges. The budget includes system instructions, focus/outline metadata, page labels and a completion reserve. Blank text is skipped; short passages and formulas are retained.
4. PDFSummaryAgent processes each passage sequentially. The model ignores boilerplate and marks passages with no substantive content. Intermediate summaries retain page ranges and are returned in chunk_summaries.
5. summary/reducer.py merges consecutive groups of at most four summaries, carrying singleton tails forward. Further levels reduce to one coherent document summary. With 13 prepared passages and groups of four: 13 map requests + 3 intermediate merges + 1 final merge = 17 successful calls.
6. summary/prompts.py defines grounding rules and final format: overview, main topics, key takeaways. The outline supplies structure only; it cannot supply unsupported facts.
7. summary/llm.py handles non-streaming intermediate requests. summary/streaming.py streams the final response for /ask. Both enforce SUMMARY_INPUT_TOKENS (default 5500) and reserve SUMMARY_OUTPUT_TOKENS (2048). GPT-OSS requests use low reasoning effort. Intermediate notes are capped at 1200 characters so subsequent merges fit. SDK retries are disabled; streams close on completion, failure or cancellation.
8. summary/retry.py honors Retry-After seconds/dates with bounded waits up to 120 seconds. It retries transient failures before publication. Final text already shown is never replayed, and deterministic streamed output-limit failures stop immediately. HTTP 413/permanent errors get clear safe messages and are not resent unchanged.
9. summary/service.py connects storage and the agent; orchestration/summary_workflow.py publishes final prose deltas through /ask and appends source coverage after success. Intermediate map/reduce notes remain internal. Boilerplate-only markers are buffered and never shown. Optional combined summaries also stream their final merge.
10. summary/checkpoints.py caches complete stages in SQLite by document, model, prompt and configuration for seven days. Retrying the same request reuses successful work, including the final summary. Empty/partial/failed/cancelled stages are not cached. PDF deletion clears checkpoints. Cache storage errors are best effort and do not discard a successful model result.
11. Large-PDF task deadlines scale with registered chunk count (600 seconds minimum, 7200 default maximum). Opt-in SSE carries page progress, quota waits, text, errors and a completion marker, with 10-second heartbeats. Existing plain-text API clients retain their contract. The frontend requests SSE and displays progress separately from answer text.

Files implementing the summary flow stay under 80 lines each. Obsolete representative-sampling helpers were removed; see service-cleanup.md. Frontend buffering and rendering are described in streaming-logic.md.

2026-10-23 coverage update: storage now prefers every physical page of the original PDF. Indexed fallback must match the registered complete chunk set. Explicit whole-document requests clear an inherited section range; chapter requests retain it. User focus and balanced outline hints have separate budgets. The result reports actual text pages and pages without selectable text. Checkpoint version 2 invalidates the prior prompts. See all-pages-summary-retrieval.md for the current source-selection and verification details.

Limits: token counting uses the configured local generation tokenizer, otherwise conservative UTF-8 byte counts. Tune SummaryConfig for the deployed model and account quota. Intermediate outputs are bounded; merging can lose detail, so chunk_summaries remain available. The actual document is not sampled. Calls are sequential within each agent; concurrent users still share organization-level quotas. Cached work resumes for identical model/prompt/configuration, while changed requests can require new calls. Current provider quota can make a full textbook summary take several minutes.
